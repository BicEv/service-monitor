# Service Monitor (Quarkus & Java 21)

Высокопроизводительный асинхронный сервис для мониторинга доступности сайтов и веб-сервисов. Проект построен на базе фреймворка **Quarkus** с использованием возможностей **Java 21** и событийно-ориентированного подхода (**Event-Driven Architecture**).

## Ключевые особенности и архитектура
* **Виртуальные потоки (Java 21)**: Каждая сетевая проверка выполняется в изолированном виртуальном потоке через управляемый пул `@VirtualThreads Executor`. Это позволяет одновременно мониторить тысячи сайтов без нагрузки на операционную систему.
* **Слабая связанность и Kafka**: Сервис полностью изолирован от внешних инфраструктурных зависимостей (таких как отправка почты или мессенджеры). При фиксации аварии приложение выстреливает структурированное JSON-событие в брокер **Apache Kafka** через `SmallRye Reactive Messaging`.
* **Изоляция транзакций**: Сетевой ввод-вывод (HTTP-запросы) и отправка сообщений в брокер полностью вынесены за рамки транзакций. Работа с базой данных инкапсулирована в ультра-короткие транзакции с помощью ручного управления `QuarkusTransaction.requiringNew()`.
* **Защита от наслоения (Overlapping Protection)**: Благодаря конфигурации планировщика `concurrentExecution = SKIP` в связке с барьером `CompletableFuture.allOf().join()`, новый цикл мониторинга гарантированно не запустится, если предыдущая пачка сайтов ещё проверяется.
* **Отказоустойчивость сети (Resilience)**: Выделенный сетевой клиент использует встроенный механизм `@Retry` от SmallRye Fault Tolerance. При транзитных сбоях сети (Timeout, DNS-ошибки) система делает 3 автоматические попытки запроса перед тем, как зафиксировать аварию.
* **Промышленный дизайн слоев**: Приложение переведено с паттерна Active Record на классический **Repository Pattern** (`PanacheRepository`). Слой API полностью изолирован от сущностей базы данных с помощью **DTO (Java Records)** и централизованного маппинга.
* **Современный синтаксис**: Обработка и классификация сетевых исключений реализована через продвинутый **Pattern Matching для оператора switch** в Java 21.

## Технологический стек
* **Java 21** (Virtual Threads, Records, Stream API, Switch Pattern Matching)
* **Quarkus** (REST Jackson, Hibernate ORM with Panache Repositories, SmallRye Reactive Messaging Kafka, SmallRye Fault Tolerance Scheduler)
* **PostgreSQL** (Основная БД в продакшене)
* **H2 Database** (Встроенная БД в памяти для тестового профиля)
* **REST Assured & Awaitility** (Интеграционное тестирование асинхронных потоков и REST-слоя)

## Как запустить локально

### 1. Режим разработки (Dev Mode)
Запустите приложение в режиме live-coding. Благодаря концепции **Quarkus Dev Services**, фреймворк автоматически обнаружит отсутствие настроек и сам поднимет временные контейнеры с **PostgreSQL** и **Apache Kafka** в вашем Docker Desktop:
```bash
./mvnw quarkus:dev
```
* Документация API (Swagger UI) доступна по адресу: `http://localhost:8080/q/swagger-ui/`
* Панель управления и стриминг сообщений Kafka (Dev UI) доступны по адресу: `http://localhost:8080/q/dev-ui/`

### 2. Запуск тестов
Прогон интеграционных тестов многопоточности, таймингов планировщика и REST-слоя на базе H2 в памяти без обращения к реальной сети и Docker:
```bash
./mvnw test
```

### 3. Сборка в Docker
Сборка классического JVM-образа:
```bash
./mvnw package
docker build -f src/main/docker/Dockerfile.jvm -t ru.bicev/service-monitor .
```
